  [1] 집에서 실행하려면 이것부터
----------------------------------------------------------------------------------------------------
   준비물   설치 확인 방법
   ------   -------------------------------------------------------
   JDK 8+   명령창에서  javac -version
   톰캣 9   webapps 폴더가 있는지 확인
   MySQL 8  명령창에서  mysql -u root -p 로 접속되는지 확인
   이클립스 Enterprise 버전 (JSP 개발용)

   1) MySQL 준비
        수업 때 받은 funweb_setup_all.sql 을 실행한다.
        mysql --default-character-set=utf8mb4 -u root -p < funweb_setup_all.sql
        ** --default-character-set=utf8mb4 를 꼭 붙인다.
           안 붙이면 한글 이름이 깨져 저장되어 조회가 안 된다. **

   2) 이클립스에 프로젝트 가져오기
        File - Import - Web - WAR file 을 골라 이 war 를 선택한다.

   3) 톰캣에 올려서 실행
        프로젝트 우클릭 - Run As - Run on Server

   4) 브라우저에서 확인
        http://localhost:8080/프로젝트이름/

  [2] 읽는 순서  ** 이 순서대로 읽어야 이해가 잘 된다 **
----------------------------------------------------------------------------------------------------
   순서   파일                    무엇을 하는 파일인가          읽는 데 걸리는 시간
   ----   ---------------------   ---------------------------   ------------------
    1     MemberVO.java           데이터를 담는 상자             10분
    2     MemberDAO.java          SQL 을 실행하는 곳             40분
    3     MemberService.java      업무 순서를 판단하는 곳        20분
    4     MemberController.java   요청을 받고 화면을 고르는 곳   40분

   ** 왜 이 순서인가 **
   안쪽(데이터) 에서 바깥쪽(화면) 순서다.
   Controller 를 먼저 읽으면 Service, DAO 를 모르는 상태라
   무슨 말인지 알기 어렵다.

   ** 각 파일 맨 끝에 [혼자 확인해 보기] 문제가 있다.
      다 읽은 뒤 답을 가리고 스스로 설명해 보자. **

  [3] 전체 그림  ── 값이 오가는 길
----------------------------------------------------------------------------------------------------
   브라우저          Controller         Service          DAO           MySQL
   ────────         ──────────        ────────        ─────         ───────
   폼 전송   ──>   입력값 꺼내기
                   VO 상자에 담기 ──>  업무 판단 ──>  SQL 실행 ──>  검색/저장
                                                                        │
                   화면 고르기   <──  결과 전달  <──  결과 읽기  <────┘
   화면 표시 <──   redirect / forward

   ** 갈 때는 오른쪽으로, 올 때는 왼쪽으로.
      화살표가 반드시 짝을 이룬다는 점을 기억하자. **

  [4] 계층별 "아는 것 / 모르는 것"   ── 이게 MVC 의 핵심이다
----------------------------------------------------------------------------------------------------
   계층          아는 것                          모르는 것
   -----------   ------------------------------   ----------------------
   JSP(화면)     화면 그리기                       SQL, 업무 순서
   Controller    요청 분기, 화면 선택              SQL, 업무 규칙
   Service       업무 순서와 조건                  SQL, 화면
   DAO           SQL 과 커넥션풀                   화면, 업무 순서

   ** 직접 확인해 보기 **
     MemberService.java 에서 "select" 를 검색해 보자  -> 하나도 없다
     MemberController.java 에서 "out.print" 를 찾아보자 -> 하나도 없다
     MemberDAO.java 에서 "request" 를 찾아보자        -> 하나도 없다
   -> 각자 자기 일만 하고 있다는 증거다.

   ** 이렇게 나누면 좋은 점 **
     DB 를 오라클로 바꾼다  -> MemberDAO 만 고친다
     화면 디자인을 바꾼다   -> JSP 만 고친다
     가입 규칙을 바꾼다     -> MemberService 만 고친다

  [5] 기능별로 코드 따라가기  ── 종이에 그려 가며 읽어 보자
----------------------------------------------------------------------------------------------------
   [로그인]
     login.jsp 폼 전송
       -> Controller.doHandle -> login()
         -> Service.login()
           -> DAO.isExisted()  -> select ... where id=? and pwd=?
         <- true/false
       -> 성공 : session 에 userId 저장 + index.jsp 로 redirect
          실패 : loginMsg 담아 login.jsp 로 forward

   [회원가입]
     join.jsp 폼 전송
       -> Controller.join()
         -> Service.join()
           -> DAO.isDuplicated()  <- 중복이면 여기서 중단
           -> DAO.insertMember()  -> insert into ...
       -> 성공 : 세션 저장(가입 즉시 로그인) + redirect

   [회원수정]  ** 2단계인 것에 주의 **
     1단계 modifyForm.do : DAO.selectMember() 로 기존 정보를 조회해
                           화면 입력칸에 채워 준다
     2단계 modify.do     : DAO.updateMember() 로 실제 저장

   [회원탈퇴]
     withdrawForm.do -> 비밀번호 입력 화면
     withdraw.do     -> Service 가 비밀번호 확인 후 삭제
                        -> 성공하면 session.invalidate() 로 로그아웃까지

   [아이디/비밀번호 찾기]
     아이디 찾기   : 이름 + 이메일 (2개)
     비밀번호 찾기 : 아이디 + 이름 + 이메일 (3개)
     -> 비밀번호가 더 중요한 정보라 확인 항목이 하나 더 많다

  [6] 꼭 기억할 개념 10가지
----------------------------------------------------------------------------------------------------
    1. this.id = id
         앞은 객체의 변수, 뒤는 매개변수. this 를 빼면 값이 저장되지 않는다.

    2. 물음표(?)와 setString
         SQL 의 값 자리를 비워 두고 나중에 채운다.
         글자를 이어붙이면 SQL 삽입 공격에 뚫린다. 자리번호는 1부터.

    3. executeQuery 와 executeUpdate
         select        -> executeQuery   (결과표를 돌려준다)
         insert/update/delete -> executeUpdate (행 개수를 돌려준다)

    4. rs.next() 를 if 로 감싸야 할 때
         count 조회는 항상 1행이라 그냥 호출해도 된다.
         일반 조회는 0행일 수 있어 if (rs.next()) 로 검사해야 한다.

    5. where 절
         update, delete 에서 where 를 빼면 전체가 바뀌거나 지워진다.
         되돌릴 수 없으므로 실행 전에 반드시 확인한다.

    6. try-with-resources
         괄호 안에서 연 자원은 블록이 끝나면 자동으로 반납된다.
         반납하지 않으면 커넥션풀이 바닥나 사이트가 멈춘다.

    7. 조기 종료 return
         조건에 걸렸을 때 return 으로 즉시 끝내지 않으면
         아래 코드까지 실행되어 오류가 난다.

    8. redirect 와 forward
         성공 후 이동 -> redirect (주소창 바뀜, request 값 사라짐)
         실패 안내     -> forward  (주소창 그대로, request 값 유지)

    9. session 과 request
         session : 브라우저를 닫거나 로그아웃할 때까지 유지 (로그인 상태)
         request : 요청 한 번 동안만 유지 (실패 메시지)

   10. 수정/탈퇴 아이디는 세션에서
         폼에서 받은 아이디를 믿으면 남의 정보를 고치거나 지울 수 있다.

  [7] 오류가 났을 때 찾아보는 표
----------------------------------------------------------------------------------------------------
   증상                                원인과 확인할 곳
   ---------------------------------   ------------------------------------------
   404 오류                            주소 오타 / doHandle 에 그 분기가 없음
   500 NullPointerException            init 에서 Service 를 안 만들었거나
                                       null 인 상자에 getter 를 부름
   500 커넥션풀 오류                    context.xml 의 name 과 DAO 의 lookup
                                       이름이 다름 ("jdbc/jspdb")
   로그인이 계속 실패                   폼의 name 과 getParameter 이름 불일치
   한글이 ??? 로 저장됨                 setCharacterEncoding 이 없거나
                                       getParameter 보다 뒤에 있음
                                       또는 MySQL 접속 문자셋 문제
   경고창이 안 뜸                       forward 대신 redirect 를 씀
   수정 화면이 비어 있음                modify.jsp 를 주소창에 직접 입력함
                                       (modifyForm.do 로 들어가야 함)
   저장은 되는데 결과가 false           executeQuery 를 씀 (executeUpdate 여야 함)
